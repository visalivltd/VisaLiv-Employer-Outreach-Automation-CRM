# 1. Purpose

The Workflow Module is responsible for tracking the lifecycle of every employer application generated by the system.

Each successful email creates a workflow record that represents the current status of that application.

The Workflow Module provides complete visibility into every application sent on behalf of students.

---

# 2. Objectives

The Workflow Module is responsible for:

- Creating workflow records
- Tracking application status
- Maintaining application history
- Providing workflow information to the Dashboard
- Supporting future workflow stages

---

# 3. Scope

## Included (MVP)

- Workflow Creation
- Initial Status Tracking
- Workflow History
- Workflow Search
- Workflow Summary

## Excluded (Future)

- Interview Tracking
- Employer Replies
- Offer Management
- Rejection Tracking
- Follow-up Automation
- Reminder System

---

# 4. Primary User

Current User

- Admin

The Admin monitors workflow progress through the CRM.

---

# 5. Module Overview

Whenever an email is successfully delivered to an employer, the system creates a workflow entry.

Each workflow entry represents one student application.

The Workflow Module maintains the current status and history of every application.

---

# 6. Functional Requirements

The system shall:

- Create a workflow after a successful email.
- Assign an initial workflow status.
- Maintain workflow history.
- Allow workflow search.
- Display workflow summary.
- Provide workflow data to the Dashboard.

# 10. Validation Rules

## Workflow Creation

- Student must exist.
- Employer must exist.
- Successful email is required.

---

## Workflow Status

Only valid workflow statuses are allowed.

---

# 11. Business Rules

### WORKFLOW-001

A workflow is created only after a successful email.

---

### WORKFLOW-002

Each workflow belongs to one Student and one Employer.

---

### WORKFLOW-003

Each successful email creates one workflow record.

---

### WORKFLOW-004

Workflow status must always be available.

---

### WORKFLOW-005

Workflow history must be preserved.

---

### WORKFLOW-006

Workflow records are read-only unless updated by future workflow actions.

### State Definitions

| State | Description |
|---------|-------------|
| Created | Workflow record has been generated. |
| Application Sent | Application email has been delivered successfully. |
| Employer Responded | Employer has responded to the application. |
| Interview Scheduled | Interview has been scheduled. |
| Interview Completed | Interview process completed. |
| Offer Received | Employer has issued an offer. |
| Hired | Student has been hired. |
| Rejected | Application rejected by employer. |
| No Response | No response received from employer. |

# 17. Success Criteria

The Workflow Module is considered complete when:

- Workflow records are created successfully.
- Initial status is assigned correctly.
- Workflow history is maintained.
- Dashboard receives workflow information.
- Future workflow stages can be added without redesign.

---

# 18. Notes

The Workflow Module tracks the lifecycle of employer applications.

It does not participate in employer selection, queue generation, or email delivery.

Its responsibility begins only after a successful email has been sent.
